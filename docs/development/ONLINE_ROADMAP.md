# 개인 문제은행의 온라인 전환 계획

## 현재 범위와 목표

누구나 코드 사본을 받아 자기 PC에서 문제를 만들고 학습할 수 있다. 관리자 게시·초대 3명 모델은 최신 요구에서 제외되었다. 개인 PC용 작성/가져오기/내보내기/채점/기록 기능이 현재 범위이며, 온라인 계정·DB·호스팅은 아직 구현·연결하지 않았다.

후속 목표는 가능하면 무료 한도 안에서 자신의 문제은행을 온라인으로 사용하는 방식이다. 코드만 공유하고 각 설치본의 데이터·계정·자격 증명은 분리한다. 저장소 공개 범위와 라이선스도 별도 결정이다.

## 후보 구성

Vercel Hobby + Supabase Free. 공식 조건과 출처는 [온라인 운영 안내](../HOSTING.md)에 있으며 도입 당시 다시 확인한다. 유료 전환이나 공개 배포를 자동 수행하지 않는다.

```text
각 사용자의 코드 사본
  ├─ 본인의 웹 프로젝트 → 고유 접속 주소
  └─ 본인의 Supabase 프로젝트
       ├─ 실제 인증과 소유권
       ├─ 개인 문제은행과 불변 revision
       └─ 개인 시도·복습·계획
```

## 구현해야 할 항목

1. 로컬 자동 세션을 Supabase 등 실제 인증으로 교체한다. 클라이언트가 보낸 사용자/역할 값을 신뢰하지 않는다.
2. 인증된 사용자가 자신의 문제은행을 작성·편집·내보내고 공부할 수 있도록 owner_id와 서버 권한/RLS를 설계한다. 기존 개인 앱의 모든 콘텐츠 소유 가정을 인터넷에 적용하지 않는다.
3. `Storage`를 DB 트랜잭션 기반 구현으로 교체하고 스키마·마이그레이션·RLS 정책을 제공한다. 로컬 파일 어댑터를 서버리스에 복사하지 않는다.
4. 단일 소유자 온라인 설치부터 검증한다. 여러 사용자가 같은 설치본에 가입하는 기능은 가입 범위와 격리 요구를 먼저 결정한다. 과거 초대 3명 제한을 자동으로 되살리지 않는다.
5. 출제/편집 API의 목적별 권한, 교차 접근 차단, 중복 제출, 수정 충돌, 과거 revision 보존을 실제 인증·DB로 재검증한다.
6. 승인된 HTTPS 출처를 명시적으로 구성한다. 현재 localhost 제한을 무조건 삭제하지 않는다.
7. 각자가 자기 프로젝트에서 재현할 수 있도록 환경변수 예제, DB 초기화, 소유자 설정, 누락 오류와 업데이트/백업 방법을 제공한다. 비밀값은 포함하지 않는다.
8. 인증 장애, 휴면/무료 한도 초과와 데이터 복구 절차를 다룬다.
9. 별도 설치본에서 작성·풀이·기록·JSON 이동까지 검증한 뒤에만 온라인 배포 명령이나 버튼을 안내한다.

## 승인과 문서

코드/문서 작업과 PR는 기존 사용자 요청에 포함된다. 외부 계정 연결, 저장소 공개 변경, 라이선스 부여, 유료 서비스, 중요한 보안 변경과 실제 배포는 별도 승인 사항이다.

README와 `docs/INSTALLATION.md`, `QUESTION_BANK.md`, `SELF_HOSTING.md`, `HOSTING.md`는 사용자용이다. 기술 설계·테스트·진행 이력은 `docs/development/`에 둔다.
