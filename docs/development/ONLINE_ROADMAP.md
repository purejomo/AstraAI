# 무료 온라인 운영과 독립 설치를 위한 전환 계획

## 사용자 요구

2026-11-07 추가 요구:

- 개인·비상업용으로 가능하면 월 비용 없이 온라인 접속 제공
- 한 운영자의 서비스에 모두 종속되지 않고, 다른 사람도 코드를 받아 자기 설치본의 관리자로 운영
- README는 설치·사용·운영 중심, 개발·테스트·설계는 별도 디렉터리

독립 설치마다 현재 기준 관리자 1명과 학습자 3명을 둔다. 다른 운영자의 프로젝트는 별도 데이터·계정·자격 증명을 사용한다. 소스 코드 공개 범위와 라이선스는 아직 결정되지 않았으며 이 변경에서 공개 설정을 바꾸지 않는다.

## 현재 완료 범위

개인 PC용 앱과 로컬 저장, 관리자 문제은행 흐름, 서버 채점, 학습 기록·복습·계획, 반응형 UI와 자동 테스트를 구현했다. 온라인 계정·DB·호스팅을 구현/연결한 것은 아니다. 사용자용 설치 명령은 최적화 빌드와 `npm start`를 기준으로 안내한다.

## 권장 목표 구성

Vercel Hobby + Supabase Free. 현재 공식 무료 조건과 근거는 [온라인 운영 안내](../HOSTING.md)에 기록했다. 무료 한도는 운영 당시 다시 확인하며 유료 전환이나 공개 배포를 자동으로 수행하지 않는다.

```text
각 운영자의 코드 사본
  ├─ 운영자 자신의 웹 프로젝트 → 고유 접속 주소
  └─ 운영자 자신의 Supabase 프로젝트
       ├─ 관리자/학습자 인증
       ├─ 학습팩과 불변 개정본
       └─ 사용자별 시도·복습·계획
```

## 구현해야 할 항목

1. 프로덕션 모드에서는 임의 `profileId` 선택으로 세션을 만들지 않는다. 실제 Supabase 인증·서버 프로필 역할로 사용자 식별을 교체한다.
2. 새 설치본의 소유자가 검증된 본인 계정으로 첫 관리자를 등록하게 한다. 공개 요청의 선착순 관리자 등록이나 클라이언트 role 값은 사용하지 않는다.
3. `Storage` 구현을 DB 트랜잭션/권한 모델로 교체하고 스키마·마이그레이션·RLS 정책을 제공한다. 파일 어댑터를 Vercel에 복사하는 것으로 대체하지 않는다.
4. 초대 3명 제한, 만료·1회 소비, 공개 가입 차단, 공유/취소를 실제 사용자 기준으로 구현한다.
5. 정답 보호, 사용자 간 교차 접근 차단, 중복 제출, 개정본 보존을 실제 인증·DB 조합으로 재검증한다.
6. 승인된 HTTPS 출처와 로컬 출처를 명시적으로 설정한다. 현재 localhost 제한을 무조건 삭제하는 방식은 사용하지 않는다.
7. 다른 운영자가 자기 프로젝트에서 재현할 수 있도록 환경변수 예제, DB 초기화, 관리자 등록, 설정 누락 오류와 업데이트/백업 절차를 제공한다. 실제 비밀값은 코드에 포함하지 않는다.
8. 초기화되지 않은 DB, 인증 공급자 장애, 휴면/무료 한도 초과, 초대 메일 제한을 사용자에게 이해할 수 있는 오류로 표시한다.
9. 새 운영자의 별도 프로젝트에서 설치·로그인·게시·풀이·기록 분리를 검증한 후에만 사용자용 온라인 배포 명령과 버튼을 추가한다.

## 권한과 범위

코드/문서 작업과 공개 요금 안내 조회는 진행할 수 있다. 외부 계정 연결, 저장소 공개 전환, 라이선스 부여, 과금 설정, 중요한 보안 변경과 실제 공개 배포는 사용자의 명확한 결정을 전제로 한다. 현재 저장소의 PR 생성 권한은 기존 사용자 요청에 포함되어 있다.
