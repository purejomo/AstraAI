# Codex Cloud 단독 개발 프롬프트 (Vercel 없이 1차 구현)

너는 GitHub 저장소 `purejomo/AstraAI`의 구현 책임자다. **현재 단계는 Codex Cloud 안에서만 개발·검증하는 단계**다. Vercel, Supabase, 유료 API 및 다른 외부 서비스 연결이나 배포를 전제하지 않는다.

## 사전 확인

- 먼저 `AGENTS.md`, `docs/development/PRD_FINAL.md`, `docs/development/ARCHITECTURE.md`, `docs/DATA_CONTRACT.md`, `docs/development/IMPLEMENTATION_PLAN.md`, `schemas/study-pack.schema.json`, `examples/sample-study-pack.json`을 읽어라.
- 이 문서의 지시는 **1차 개발 단계에 한해** 이전 문서에 남은 Vercel/Supabase 즉시 연동 일정보다 우선한다.
- GitHub 저장소가 읽기·쓰기 가능하면 기능 브랜치를 만들고 변경을 커밋한 뒤 PR로 정리하라. 권한이 없으면 코드와 테스트는 진행하고 막힌 점을 명확히 보고하라.

## 제품의 핵심 구조

관리자 본인이 자신의 ChatGPT Pro에서 학습 자료(PDF/이미지)를 직접 올리고 문제은행 JSON 파일(`study-pack.json`)을 생성한다. 앱은 프롬프트 복사와 JSON 가져오기/검증/미리보기/게시를 제공한다. 실제 학습자는 3명이며 각자의 시험 목표·퀴즈·오답·복습 이력을 가진다. 앱 안에서 OpenAI API, 실시간 LLM 또는 ChatGPT 세션 토큰을 사용하지 않는다.

## 구현 요구 (Next.js + TypeScript)

1. 차분하고 명료한 PC/모바일 반응형 디자인. `taste-skill`의 디자인 원칙 참고하되 Astra 브랜드 및 화면 리소스 복제 금지.
2. 관리자: 학습팩 제목/수준/문항 수 입력 -> 프롬프트 생성 및 복사 -> ChatGPT에서 생성한 JSON을 앱에 가져오기 -> JSON Schema + 참조 무결성 검증 -> 오류 안내 및 미리보기 -> 게시.
3. 학습자: 학습팩 목록, 개념 요약/FAQ, 4지선다 문제, 서버 채점 및 해설, 플래시카드, 모의고사, 오답 노트, 복습 일정, 학습 계획, 성취 대시보드.
4. 초기에는 테스트 가능한 **로컬 데모 스토리지**를 사용하되 저장/조회 인터페이스를 추상화해서 다음 단계에 Supabase를 연결하기 쉽게 만들 것.
5. 데모 사용자 3명 프로필과 관리자 프로필을 제공하되, 실제 인증과 혼동하지 않도록 **개발/데모 전용 계정 전환**이라고 명확히 표시. 공유 인터넷 공개 서비스에서는 데모 인증으로 접근 통제를 대신할 수 없음을 문서화.
6. 채점과 오답 스케줄은 결정적 규칙 엔진으로 구현. 실시간 AI와 같은 표현을 사용하지 않음.
7. 샘플 JSON이 유효하게 로딩되도록 하고, 잘못된 JSON, 중복 ID, 없는 concept_id, 4지선다 위반, 잘못된 정답 값 등 실패 사례를 검증.

## 작업 방식 및 테스트

- 단순 문서 작성에 그치지 말고 코드 구현까지 수행.
- 기능 우선순위: 기본 화면 → 관리자 JSON 흐름 → 학습자 퀴즈/채점/기록 → 오답/계획/대시보드 → 플래시카드/모의고사 → 디자인 정리.
- 사용 가능한 Cloud 브라우저 테스트 도구(agent-browser 또는 Playwright)를 확인하여 실제 페이지에서 적어도 1440px/390px 테스트. 지원되지 않는 테스트는 대체 테스트와 제한사항 보고.
- `npm install`, 린트, 단위/통합 테스트, `npm run build` 실행. 실패하면 고치고 재검증.
- 실사용자 인증·영속 DB·인터넷 상시 접속은 **2차 배포 단계**로 남겨둔다. 해당 기능을 이미 완료했다고 주장하지 말 것.
- 개발 진행상황, 명령/테스트 결과, 미완료 사항을 `docs/development/IMPLEMENTATION_PLAN.md`에 기록.
- 완료 시 실행 방법(Windows PowerShell 포함), 구현 목록, 검증 결과, GitHub 커밋/PR, 차후 배포 시 필요한 승인만 간결히 보고.

## 승인 및 비용

코드 추가, 테스트, 안전한 의존성 설치, 기능 브랜치 커밋은 사전 승인이 불필요하다. 유료 서비스, 외부 사용자에게 배포, 실제 데이터 삭제, 보안 완화, 외부 계정 연결은 반드시 승인받는다. API 사용료는 0원. 인증 토큰, 비밀번호, 쿠키, 개인 학습 자료는 GitHub에 올리지 말 것.

**지금 바로 개발을 시작하라. 막히지 않는 일은 계속 진행하고, 구체적 차단 요인이나 승인 필요 사항만 질문하라.**
